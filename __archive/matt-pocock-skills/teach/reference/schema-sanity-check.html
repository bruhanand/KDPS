Schema sanity-check

Six things to look for whenever the AI hands you database tables for KDPS. You're not writing the schema — you're checking it doesn't quietly break the spine.

🗄️ Hold this: a database is just tables (rows & columns). Your job is to confirm the most important table — stock — is a ledger you add to, not a count you overwrite, and that the business rules live where they should.
1

Stock is a ledger, not a count

Is there a separate movements table, append-only?

WANTA stock_movement table; rows only added; on-hand = SUM(qty).

FLAGA stock_qty column updated in place on each sale — no history, no audit.

2

Size × Colour survive

Can you tell a size 8 White from a size 10 Black?

WANTThe sku table has its own size and colour columns.

FLAGStock tracked at style level only. "SKU = Style × Size × Colour" — never break it.

3

The commercial model lives on the brand

Set once, inherited by all its SKUs?

WANTOne commercial_model column on brand (Buy&Sell / Correction / SOR / Consignment).

FLAGThe model copied onto every product, or typed at each sale — it'll drift out of sync.

4

Money is derived, not typed

Profit computed from cost & revenue?

WANTCost (from PT/invoice) and revenue (from the sale) stored; profit calculated.

FLAGA hand-fillable profit column. Profitability is always derived.

5

Tables link by id, facts aren't repeated

Primary keys & foreign keys in place?

WANTEach table has an id (primary key); links via brand_id, sku_id (foreign keys).

FLAGThe same brand/SKU details copy-pasted across many rows — guaranteed to go inconsistent.

6

State & GST are modelled as data

Two GSTINs, dated tax — not hard-coded?

WANTEach store maps to a state GSTIN; tax rates are date-effective rows, not numbers in code.

FLAGA single GST rate baked into the code, or stores with no state mapping.

🧭 If in doubt, ask the AI to explain a table: "Walk me through this table — what's one row, what gets added vs updated, and how does on-hand get calculated?" If the answer involves updating a stock number in place, push back. The spine wants add, never overwrite.
