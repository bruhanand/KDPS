External gates — confirm before they bite

Three outside systems + one CA conversation are assumed, not verified. They have lead time — start chasing them now, in parallel with D9.

Spike #1 · Ten Software POS API biggest risk

Two make-or-break answers: can it accept pending-inward qty per store, and export line-item sales?
Needed before you build Selling. Pre-decide the "no API" fallback + build-own-POS go/no-go · August deadline.

Spike #2 · Tally via TaxOne

Actually post a sales + a transfer voucher to TallyPrime. Confirm deterministic import (no AI re-interpretation) + idempotency. Generate one IRN + one e-way bill in sandbox.
Needed when you build the Tally-sync module (near the end).

Spike #3 · Barcode tool

Sample sticker · Code 128 generation · HID-mode scanning (not keyboard-wedge).
Needed when you build Selling / stock movement.

The CA sitting

How many GSTINs/entities · one Tally company or two · e-invoicing applicability · SOR invoice-vs-challan · ledger structure.
One conversation unblocks D6 vouchers, D4 P&L and SOR booking at once.

The build road — thin slices, in architecture order

Each slice runs top-to-bottom (one real document → ledger → screen). Start with the simplest real path; end the first proof at the ledger, before POS.

0

Foundation scaffold the one flat step

Repo · database · migrations · login + RBAC (reconciling D4+D8) · CI gate · component library (₹ Lakh/Crore) · seed masters · CLAUDE.md. No business logic.
1

Walking skeleton — one branded shipment → ledger

One real invoice: booking → GRN → PT → stock + vendor postings → a screen showing accurate cross-store stock. Validated by a golden file. First client win: accurate stock before POS is touched.
2

Booking + order-vs-received tracking

Build first (Aug = peak booking). Branded capture → AI draft → human confirm. Resolve the booking-price conflict in the spec first.
3

Non-branded inbound — the AI PT maker

~99% of warehouse volume, AI on the critical path. Invoice read → chat fill → editable PT → stock-in. Needs the per-category margin list.
4

Payments spine

Payable → eligibility gate → maker≠checker≠payer → manual pay (UTR) → bank-statement auto-close. Vendor GSTIN/bank cleanup precedes this.
5

Outbound + the POS edge gated on Spike #1

"One machine, eight settings" behind a swappable POS adapter. Fix the cross-state IGST bug here. No API → triggers the build-own-POS fork.
6

Offers engine

Paste circular → AI draft → confirm · item-level stacking · bill-discount split back to lines · applied-vs-rulebook reconcile. Lock "which offer wins" first.
7

Tally sync gated on Spike #2 + CA

Deterministic export → TaxOne · daily B2C voucher per store per rate · idempotent voucher numbers · daily tie-out queue.
8

Analytics foundation + WhatsApp digest

The metrics layer → 9pm exception digest → discount-leakage watchdog (zero ML, highest ROI). Defer forecasting until clean seasons exist.

Full reasoning, the toolchain map and the research basis live in the two build docs → How we build · Build-readiness audit.
