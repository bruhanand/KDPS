POS Requirements

1.Data we need to read from the POS

  • Sales (line items) — bill date, bill no, store, salesman, customer, phone, barcode, item, brand, colour, size, design no, sub-category, gender, fit, season, qty, rate, gross, disc%, disc amt, net, bill amount, cash/card/credit
  • Stock-on-hand per store — store, barcode, qty, as-of date/time
  • Daily collection per store — store, date, cash, card, UPI, credit, total
  • Returns & exchanges — bill no, original bill no, barcode, qty, amount, type, reason
  • Item master — barcode, item, brand, colour, size, MRP, HSN, category, season
  • Historical export (one-time) — past sales & stock per store/barcode

2.Data the POS must accept from us

  • Item / price master
  • Per-store allocation (pending-inward) — barcode, store, qty
  • Stock hold / reservation — barcode, store, qty
  • Stock transfer — from-store, to-store, barcode, qty, ref
  • Offers / EOSS (later)
  • Barcode — return the generated code to us, or accept ours

3.Access & technical

  • API documentation
  • Access credentials + test/sandbox environment
  • Method: REST API / webhook / scheduled export
  • Authentication + rate limits
  • Format: JSON or CSV/Excel
  • Frequency per feed (real-time / every few minutes / end-of-day)
  • Stable record IDs (so a re-pull does not double-count)
  • Barcode as the shared key, both directions

4.Please confirm

  • ★ Can the POS export line-item sales automatically (API / scheduled file)?
  • ★ Can the API accept a pending-inward / incoming-transfer quantity?
  • Can it accept a hold / reservation (reduce sellable without removing stock)?
  • How does it record an exchange — single "exchange", or return + new sale? Linked to the original bill?
  • Can it return a generated barcode to us, or accept barcodes we send?
  • What is available today, and the timeline for the rest?
