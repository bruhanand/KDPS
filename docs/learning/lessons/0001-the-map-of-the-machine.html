The Map of the Machine

🎯 Goals — after this lesson you can

What you already have (we build on it, not repeat it)

From your earlier learning you know the four boxes: 🖥️ Screen · 🧠 Brain · 🗄️ Memory · 🔌 Outside World. Today those boxes stop being an idea and become real folders in your own repo.

1The one shape

Every single thing KDPS does — every click in every store — travels this same road:

🖥️ React screen→ 🌐 HTTP request→ 🧠 Django + DRF→ 🗄️ PostgreSQL→ back the same way
Box (you know this)Real thing (🟦 technical)Folder in the repo
🖥️ ScreenReact PWA — the pages the stores seeapp/frontend/
🧠 BrainDjango + DRF — rules, checks, answersapp/backend/
🗄️ MemoryPostgreSQL — every table, every ledger rowno folder — it's a running database (Render / Docker)
🔌 Outside worldRender hosting, the Gemini AI readerrender.yaml · app/backend/aiagents/

P0 is mostly about the 🧠 Brain folder — that's where reading skill pays off first.

2The backend — who owns what

Open app/backend/ and you see ~13 folders. They are not random. There are three kinds:

  • 1 kernel — core/ — the hard rules everything must obey.
  • 1 switchboard — config/ — settings + which app answers which URL.
  • 10 business apps — one folder per business area. Plus tests/ — the proof it all works.
FolderOwns (one line, plain words)Business link
core/The kernel: money as paise, append-only ledgers, document rules, voucher numberingThe 12 rules live here in code form
config/Settings + the master URL switchboard (config/urls.py)—
accounts/Users, login, tokens, rolesWho may do what
masters/The nouns: stores, brands, seasons, GSTINs, SKU lookup🟧 Master data (D8)
files/Uploaded files (PT files, invoices)🟧 PT/invoice uploads
vendors/Vendors and bookings🟧 D1 vendor & booking
inbound/Goods arriving: GRN, PT injection🟧 D2 inbound
ptmapper/Brand PT file → KDPS format, + the human review queue🟧 PT mapping
stockledger/Quantity movements of stock — append-only🟧 stock truth
finledger/Money value movements + the trial-balance health check🟧 money truth
outbound/Goods going out: transfers, RTV, write-offs🟧 D3 outbound
aiagents/The AI edge — document reading (Gemini)Rule: AI at edges only
tests/40+ test files proving the above behavesTrust
The pattern to remember

Ask: "is this about quantity or value?" Quantity → stockledger. Money value → finledger. That split is one of the deepest design choices in KDPS, and you just learned to see it in the folder names.

3The repeating anatomy — every app has the same organs

Everyday version first. Think of each app as a small restaurant:

RestaurantFile (🟦)Its job in plain words
📋 The menuurls.pyThe list of things you may ask for, and which waiter serves each
🤵 The waiterviews.pyTakes the request, asks the kitchen, brings back the answer
🍽️ The plating counterserializers.pyTranslates both ways: database rows ⇄ the JSON the screen eats
📒 The store-room registermodels.pyThe shape of what's kept: each class here = one database table
🏗️ Renovation historymigrations/Every past change to the store room, in order, forever
🔑 Manager's officeadmin.pyThe back-office door (Django admin) for that app's data

This is real — here is vendors/, organ by organ:

vendors/
├── models.py       # the tables: what a vendor / booking IS
├── serializers.py  # vendor rows ⇄ JSON
├── views.py        # handles /api/vendors requests
├── urls.py         # the menu of vendor endpoints
├── migrations/     # history of vendor tables
└── agents.py       # extra: AI booking-reader hook (edge only)
Why this matters so much

Because it repeats. Learn the anatomy once → you can navigate all ten apps on day one. When a lesson says "open the serializer", you'll always know exactly which file that is, in any app. (Django's official docs call these units "applications" — docs, tutorial.)

One exception: core/ does not look like a restaurant

The kernel has no menu and no waiter — it serves no URLs. It is the law book the restaurants must follow:

money.pymoney is integer paise — never floats
ledger.pyledgers are append-only (DB triggers enforce it)
documents.pydocument lifecycle (draft→posted) + gap-free numbering
posting.py / gl.pyhow documents write balanced ledger entries
fiscal.pythe Indian financial year

4The frontend map — smaller than you fear

Folder in app/frontend/src/What lives there
pages/One file per screen. Bookings.tsx, Inbound.tsx, PtMapper.tsx, StockLedger.tsx… the name = the screen
components/Reusable pieces used by many pages (tables, buttons, badges)
shell/The frame around every page — sidebar, header, navigation
auth/Login state: who is signed in, the token
lib/Shared helpers — including the API-calling code
theme/Colours, light/dark — you already worked here (dark mode!)
main.tsx → App.tsxThe entry point: boots the app, sets up routes

5Hands-on — 4 commands, eyes open

Do these in your terminal at the repo root. The lesson only counts after this part.

# 1. See the backend map you just learned
ls app/backend
   → notice: kernel (core) + config + the business apps + tests

# 2. Prove the anatomy repeats — two different apps, same organs
ls app/backend/vendors app/backend/inbound
   → notice: models / serializers / views / urls / migrations, both times

# 3. One file per screen
ls app/frontend/src/pages
   → notice: find Bookings.tsx and StockLedger.tsx — names match screens you've used

# 4. Read the master switchboard (yes, actually read it — it's short)
cat app/backend/config/urls.py
   → notice: every line like path("api/inbound/", include("inbound.urls"))
     is the switchboard handing a URL family to one app's menu

6Quiz — which file?

Pick an answer, press Check. You get the truth immediately, with the why. Aim for 6/8+.

1. The vendor list on screen shows "vendorname" but the client wants "vendor_name" in the JSON. Which file?
2. "Money must be stored as paise, never floats." Where does that law live?
3. You want the full list of endpoints under /api/masters/…. Which file do you open?
4. The Bookings screen renders a broken table. First file to open?
5. Which app owns "how many pieces of SKU X are at Deoghar" — the quantity truth?
6. A new table must be added to the database. Which folder records that change forever?
7. A request hits /api/inbound/grns. Which file decided that the inbound app answers it?
8. Login stops issuing tokens. Which app do you open?
