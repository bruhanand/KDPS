# Mission: Top-tier engineer on the KDPS stack

## Why
Anand architects and ships KDPS by directing AI. Getting code written is now cheap; **judging it is not**. He wants to go from "I trust the review" to an engineer who can read every layer of his own system — Python · Django · DRF · PostgreSQL · TypeScript · React — knows the architecture in and out, and catches what AI gets wrong, especially on money paths. The KDPS repo is the one and only playground.

## Success looks like
- Open any file in `app/` and read it with zero syntax mystery.
- Trace any request end-to-end: screen → API → model → database → back.
- Judge a proposed feature against the architecture (the 12 rules, the five layers) *before* code is written.
- Be handed an AI-built money slice and independently find the defect its author missed.

## Constraints
- Simple English. Short lines. Lists and tables, almost never long paragraphs.
- Everything he keeps is HTML, never markdown.
- Every lesson anchors to a real KDPS file — one everyday analogy allowed, no toy projects.
- Short, focused, daily sessions — each lesson is a quick win with a quiz.
- Follow the P0→P10 order in `stack-learning-roadmap.html`; don't jump layers.

## Out of scope (for now)
- Deep ML / statistics math.
- Tally internals beyond what design needs.
- Native mobile development.
- The retired 2026-06 "vibe coder" track in `.agents/skills/teach/` — kept for history, never extended.
