P0 · Reading Code & Navigating a Repo

Course plan · 7 lessons · every lesson ends with a quiz · 8 Jul 2026 · ← back to the full roadmap
Why P0 comes before everything

Every later phase — Python, SQL, Django, React, architecture, reviewing AI — starts with opening a file and not being lost. P0 gives you that. You will not write code in P0. You will learn to read it, find it, and follow it — inside the real KDPS app, nowhere else.

1Goals — what you can do when P0 is done

  • Open any of the backend apps (vendors, inbound, stockledger…) and say what it is for and where its data lands. (This is the official P0 milestone from the roadmap.)
  • Trace one request end-to-end: browser → URL → view → serializer → model → Postgres → JSON → screen.
  • Answer "where is X defined? who uses X?" in under a minute, using search.
  • Read a git history and answer "why does this line exist?"
  • Read a real merged PR and say what changed — without running it.
  • Read a stack trace and walk straight to the guilty file:line.

2The 7 lessons — each one stands on the one before

One lesson = one skill = ~25–35 minutes. Each lesson starts with a 2-minute warm-up that re-uses the previous lesson's skill on a new target — that is the chain. Lesson 1 is built and ready; lessons 2–7 are built one at a time, after you finish the one before (so each is tuned to what you actually found hard).

L1 · 0001The Map of the Machine~25 min READY
You learnThe one shape of KDPS (screen → API → brain → database), what each of the 12 backend folders owns, and the repeating anatomy of a Django app (urls / views / serializers / models / migrations).
You can thenHear a plain-English change ("vendor list shows the wrong name") and point to the file where it lives.

L2 · 0002Reading One File, Top-Down~30 min after L1
Builds onL1 told you which file. L2 teaches you how to open it and not drown: imports → classes → methods, skim first, detail second.
You can thenOpen any Python file and give its one-line job; read urls.py as a switchboard and a small view class line by line.
Quiz"What does this real snippet do?" — 6 snippets from the repo, instant feedback.
Anchorconfig/urls.py · masters/urls.py · one small view in masters/views.py
L3 · 0003The Golden Thread — one request, end to end~35 min after L2
Builds onL1 gave the map, L2 gave file-reading. L3 walks ONE real request — the Stores list — through every station: React page → axios → /api/masters/stores → StoreListView → serializer → model → Postgres → JSON → back to the screen.
You can thenHold the full round-trip in your head. This is the single most important lesson in P0.
QuizOrder-the-stations + "a bug appears at station X — which file?" scenarios.
Anchorfrontend/src/pages → config/urls.py → masters/{urls,views,serializers,models}.py
L4 · 0004Search Is How Engineers Navigate~25 min after L3
Builds onIn L3 you followed a thread I gave you. L4 teaches you to find any thread yourself with grep/rg: find a definition, find all users of it, find where an error message comes from.
You can thenAnswer "where is X? who calls X?" in under a minute, anywhere in the repo.
QuizA terminal scavenger hunt — 6 real questions you answer by searching, then check in the page.
Anchorthe whole repo · ripgrep guide
L5 · 0005Reading History — why does this line exist?~30 min after L4
Builds onL4 found the line in space; L5 finds it in time. git log, git blame, git show on real KDPS lines — who wrote it, when, in which change, and what the message says about why.
You can thenDo code archaeology: from a suspicious line to the commit and PR that created it.
QuizArchaeology hunt on the real repo history, answers checked in-page.
Anchorgit log / blame / show · Pro Git ch. 2
L6 · 0006Reading a Change — diffs and PRs~30 min after L5
Builds onL5 read old changes; L6 reads a proposed change — the reviewer's posture. How to read a diff, what "what it quietly changed" means, reading a real merged KDPS PR without running it.
You can thenLook at a diff and say: what changed, what it touches, what could break. This is the seed of P10 (reviewing AI).
QuizA real small diff from the repo: answer "what does this change do / risk?" — graded in the page.
Anchorgit diff · a real merged PR from the repo history
L7 · 0007Reading a Failure — stack traces + the P0 exit exam~35 min after L6
Builds onEverything. A stack trace is a map written backwards — L7 teaches you to read Python and browser tracebacks and walk to the guilty file:line using L1's map + L4's search.
You can thenTake an error you've never seen and locate it. Then: the exit exam.
Exit examIn chat, I pick 2 backend apps you haven't studied. Cold, you tell me: what it's for, its endpoints, where its data lands, and you trace one request through it. Pass = P0 done, a learning record is written, P1 (Python) opens.
Anchora real traceback · any of the 11 backend apps

3How every lesson works (the rules)

PartWhat it isWhy
Goals firstEvery lesson opens with "after this you can…" — 3 concrete abilities.You asked: goals first. You always know what the win is.
Warm-up2 minutes using the previous lesson's skill on a new target.This is the chain — nothing is learned once and dropped.
TeachShort sections. Tables, not paragraphs. One everyday analogy + the KDPS version. 🟧 business term / 🟦 technical term.Your stated style.
Hands-onReal commands on the real repo, with "what to notice".Skills come from doing, not reading.
QuizIn-page, instant feedback, explanation for every answer, score at the end.The feedback loop — you know immediately if it stuck.
Exit checklistTick-boxes: "I can now…". If any box is unticked, ask me in chat before moving on.No silent gaps.
Two honest rules
  • The quiz is not the test — the repo is. A lesson counts only when you've done its hands-on part in the terminal, not just read it.
  • Ask me anything, any time. I'm your teacher in chat. "I didn't get section 3 of lesson 2" is a perfect message. Confusion reported early is cheap; confusion carried forward is expensive.
