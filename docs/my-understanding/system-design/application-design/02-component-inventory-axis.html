00

What Axis changes

Axis ships a landing-page template, not an ERP kit. What it really gives us is a token set and a set of habits. Those habits translate cleanly onto KDPS; six things visibly change.

Axis does not ship what KDPS needs most. It has no status colours, no layer accents, no data table, no sidebar, no form density. Everything below marked [ext] is an extension I authored in Axis's own idiom - low chroma, tint-not-border, hairline separation. That extension is the real design decision here, not the palette swap.

07

Verdict, honestly

What Axis buys us

  • A calmer, more current surface. Nothing competes for attention, so status colour lands harder when it appears.
  • oklch tokens. Deriving a balanced status palette becomes arithmetic rather than taste, and dark mode falls out of one block.
  • A stricter button rule: one filled button per screen. That is better than today's "brand red is the CTA" convention.
  • Hairline grids give dense ERP data a natural home - KPI rows and matrices read better with rules than with gaps.
  • It is a shadcn registry, so if the PWA ever adopts shadcn primitives, Button/Badge/Card/Input arrive as real code.

What it costs

  • Axis is a marketing template. Hero, pricing, testimonials, a logo cloud. Of ~90 files, only 6 are components KDPS uses. The ERP layer - table, sidebar, dialog, form density, the six statuses, the layer accents - is all extension work.
  • It is not currently a KDPS-shaped stack. The registry expects Next.js + Tailwind v4 + Base UI. The PWA is Vite + React + hand-written CSS. Adopting the components (not just the look) is a front-end stack decision, not a restyle.
  • Brand identity thins out. Navy, rust and brand red all disappear into near-black plus bronze. KDPS reads more like a SaaS tool and less like KDPS.
  • The warm canvas is doing quiet work. Store staff stare at these screens all day under tube light; pure white at full brightness is harsher than #faf7f2.

If you want this

Two routes, and they are genuinely different sizes.

Route A - retheme only

Keep every component and class name. Re-value index.css to these tokens, drop the shadows, widen the radii, restyle badges as tints. The app looks like this page; no component is rewritten. Touches one file plus the shell CSS.

Low riskReversible
Route B - adopt the primitives

Bring in Tailwind v4 + shadcn/Base UI properly, replace .btn/.chip/.card/.input with real components, then migrate ~30 screens. Clears the Booking.css debt by construction, because there is no longer a page stylesheet to hide in.

Stack decisionWeeks, not days

My read: this is worth seeing, and Route A is cheap enough to try on a branch and judge in the real app. But before either, the honest question is whether KDPS should look like a generic modern SaaS tool or like itself. The warm system was chosen deliberately for people who live in it eight hours a day. Axis is prettier at first glance; the warm one may be kinder by hour six.
