1 · Design tokens

The design language is the "Warm" direction, approved 28 Jun 2026: a locked navy/rust brand palette plus six semantic status colours and the five-layer band accents, on a warm paper canvas. System fonts only; ui-monospace for IDs, vouchers and money. Dark mode (PR #61) re-values these same tokens in one html[data-theme="dark"] block; light values are locked byte-identical to the original design. A palette redesign is an edit to this one file.

Dark mode splits navy into two roles: --navy brightens for text, while --navy-fill stays a dark fill under white text. Any colour rework must keep that split (the recorded gotcha from the dark-mode build).

Semantic status - six tones, each a text/background/border triple

green · ok / open / matched amber · pending / SOR / variance red · blocked / overdue / rejected blue · informational / correction purple · AI-touched (Rule 6) grey · neutral / not required

Purple is not decoration - it is the reserved marker for anything AI produced. Keep that meaning in any redesign.

Five-layer band accents

One accent per architecture layer, used for sidebar icons and the Home page bands: master #9aa1ad · documents navy · ledgers rust · controls amber · intelligence purple · edges blue · store green · outbound #b44d2d. These make the architecture legible in the UI; a redesign can restyle them but should keep the one-colour-per-layer idea.

Shape, elevation, layout constants

  • --radius: 16px outer (cards, tables) · --radius-inner: 11px (buttons, inputs) · 999px pills.
  • Two shadows only: --shadow-rest and --shadow-hover (deepened in dark mode).
  • --sidebar-w: 258px (user-resizable 210-390) · --topbar-h: 60px · content column .page-pad max 1320px.
  • ~20 bridge tokens (field-bg, row-hover, scrims, selection, drawer shadow) exist solely so dark mode can re-value them.

8 · Redesign notes & debt worth clearing on the way

The redesign path of least regret, in order:

  • 1 - Tokens first. Everything cascades from index.css. Change palette, radius, shadow, type scale there; both themes live in that one file. The dark block re-values the same names, so every token change must be made twice (light + dark) or it will only half-land.
  • 2 - Shell second. AppShell (sidebar + topbar + dropdowns) is the frame around everything; PageHeader is the top of every page.
  • 3 - Primitives third. Buttons, chips, inputs, card, table - restyle once, felt everywhere.
  • 4 - Patterns fourth. The §6 idioms (toolbar, section-card stack, modal, filter bar, line editor).
  • 5 - The six one-off surfaces last, each on its own terms.

Debt a redesign should clear:

  • Booking.css and PtMapper.css are load-bearing far beyond their names. 17+ screens import Booking.css for toolbar/section-card/modal/select; several import PtMapper.css for btn-sm/stat-card/ok-note. First move of any redesign: lift the shared classes into a real shared stylesheet (or into index.css) so "Booking" styles stop owning the whole app's anatomy. StockOnHand currently imports both because ok-note's base and its dismiss button live in different files.
  • A few components style inline instead of via tokens' classes - Stat, ApprovalSteps spacing - fine today, but they will drift from a retheme unless moved into CSS.
  • Reserved meanings to preserve: brand-red = one key CTA per screen; purple = AI-touched only; the six status tones; the layer accents; mono = IDs and money; word-plus-number for the sync light (never colour alone).
  • Locked light theme: the dark-mode build locked light values byte-identical. A redesign consciously unlocks that - fine, but say so, since the dark theme was derived from those exact values.
