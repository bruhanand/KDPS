Store Formats

EBO — Exclusive Business Outlet

Single-brand store. Brand owns inventory, manages software, decides stock. KDPS earns ~20% flat commission on monthly sales (covers rent + salaries + profit).

MBO — Multi-Brand Outlet

Multiple brands under one roof. KDPS-managed. Two sub-formats: pure male (Levis, LP, Status Quo) and mixed gender (male + female + kids). 1,000 to 6,000 sq. ft.

Three Commercial Models (MBOs)

25-18-10 Commission

Vendor supplies stock. KDPS keeps 25% on full-price, 18% during EOSS/discount. 10% goods return allowance per season.

Buy & Sell (BNS)

KDPS buys outright, sets own MRP. Two sub-types: with vendor barcode (MRP capped) or without barcode (KDPS sets price).

Consignment

Vendor's goods sit in KDPS stores. KDPS sells, takes commission. Unsold returns to vendor. Used with ~2-3 vendors only.

The PT File System — Per-Staff Excel Sheets

The current "system" is a single Google Sheets workbook with a separate tab per warehouse staff member (Debanjan, Naresh, Santosh, Mahendra, Pravin Ji, Ankit, Gulshan). Each person processes invoices into their own tab. There is no single source of truth — the master inventory is the union of all these tabs, manually merged.

Known data quality issue: The COLOR column in the master sheet mixes price tiers (PREMIUM / MEDIUM / ECONOMY) with actual visual colors (BLACK / BLUE / OLIVE). Staff must know which is which from memory.

3 Where It Breaks

The structural gaps in today's workflow
!
No Single Source of Truth
Per-staff Excel tabs, manually merged. Master inventory is a "hope it adds up." Each staff member's tab is an island.
!
No Structured Reconciliation
Invoice vs physical receipt vs PT file vs Tally — no automated matching. Errors surface days or weeks later.
!
Trust-Based Payments
No system link between invoice, GRN, PT file, and payment. Approvals happen verbally or on WhatsApp.
!
No Audit Trail
Who mapped what? Who approved which discount? Why was a classification changed? Not traceable.
!
Manual PT Creation Bottleneck
Every invoice processed by hand. Non-brand path is 100% manual: classify, price, barcode, tag. Biggest time sink.
!
Lump-Sum Payment Chaos
Bulk payments split across fractional invoices with no system to track which invoice is covered by how much.
!
SOR Return Deadlines Untracked
Missing a 60–120 day return window = KDPS owns dead stock by default. No alerts exist today. Lakhs at risk.
!
No Profitability Visibility
No per-brand, per-store P&L. Owner cannot see which brands or stores actually make money.
Scale pressure: KDPS adds ~10 new vendors every month. Each new vendor means a new invoice format, a new manual learning curve. The current manual process doesn't scale.
"Data loss rokne ke liye ek insaan chahiye jo data verify kare ki enter kiya hua data sahi hai."

4 What We Are Building

A single AI-powered operating system — fashion-retail-aware from the ground up
Module 1

IINE — Inventory Ingestion & Normalization Engine

  • Upload invoice (photo/PDF) — AI reads any vendor format
  • Auto-generates PT file in KDPS taxonomy
  • 3-way reconciliation: Invoice vs GRN vs PT (nightly)
  • Non-brand: auto-calculates MRP with margin rules
  • Every entry audited — who, when, why
Module 2

PASCS — Payment Authorization & Settlement Control

  • Payment only when Invoice + GRN + PT + TIR all align
  • Multi-level WhatsApp approval workflow
  • Lump-sum payments auto-attributed across invoices
  • Pre-tax CD calculation enforced by system
  • Bank statement auto-reconciliation

Fashion-Retail Aware — Not Generic Inventory

Size x Color Matrix
Every SKU tracked as Style x Size x Color — not just a barcode. "Size 8: 3 units, Size 9: STOCKOUT"
SOR Return Deadline Agent
Alerts at 30/15/7 days before return window expires. Missing a deadline = KDPS owns dead stock. Saves lakhs.
Season & Collection Tags
Every item carries Season (SS26, AW26), Collection (Core/Fresh/Clearance), and Age. Auto-detected from style codes.
