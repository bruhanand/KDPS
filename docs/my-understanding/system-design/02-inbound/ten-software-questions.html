KDPS · POS Integration · Q34

Questions for Ten Software

KDPS Lifestyle is building a central inventory and accounting system. The Ten Software POS stays exactly as it is in every store — we only need to exchange data with it. These questions decide how. (Forward-ready; answers close inbound decision Q34.)

A · Access & mechanics

  1. Is there an API? REST, webhook, or scheduled file export — what does the POS support today for both reading and writing data?
  2. Where is the data? One central database for all stores, or one install per store? If per store, how do we reach each one?
  3. Authentication — how is API/export access secured (keys, accounts), and can access be scoped per store?
  4. Documentation — is there API/export documentation you can share?
  5. Frequency & limits — how often can we sync (real-time, every few minutes, daily)? Any rate limits or batch-size limits?
  6. Test environment — is there a sandbox or a test store we can integrate against before touching live stores?
  7. Commercials — is API/integration access included in the current licence, or priced separately?

B · Data we want to push INTO the POS

  1. Item master — can we create/update items by barcode with MRP, tax/HSN, brand, season, category? Bulk and incremental?
  2. Pending inward — can the POS accept a "pending inward / incoming transfer" quantity per store, so the store scans against it to receive?
  3. Price & offer updates — can we update prices, and can discount/EOSS rules be set per barcode, per store, with start/end dates? Or is price the only lever?

C · Data we want to pull OUT of the POS

  1. Line-item sales per bill — barcode, qty, price, discount, store, date/time, payment mode, bill number. Available? At what frequency?
  2. Returns & exchanges at the counter — do they come through as line items with a reference to the original bill?
  3. Stock on hand per store — can we read current SOH per barcode per store (including negative values, if any)?
  4. Daily collection per store — cash / UPI / card totals per day per store?

D · The join key

  1. Barcode as the shared key — both sides must identify items by barcode. Any constraints (length, format, uniqueness)?
  2. Season reuse — some brands reuse the same barcode value in a later season. How does the POS handle a barcode it has seen before with a different item/MRP? Can items be season-scoped?
The two load-bearing answers (everything else can flex): can the POS accept a pending-inward quantity per store (B-9), and can it export line-item sales (C-11)? If either is impossible, please tell us what the closest supported alternative is.
