KDPS · Kernel · Data Model

The Kernel Data Model

The shape of the database the whole KDPS system sits on — derived from the real KDPS data, not invented. Every entity, column, key and constraint here was checked against the actual files in docs/data-from-kdps/ (the PT format, ~33 vendor PT files, the supplier/brand/store masters, the bank & daily-sales registers, real SOH + sale lines, the AMM list, the offer rulebook, the DN/CN register).

27 June 2026 · Ground-truth kernel schema · Grounds & refines consolidation/data-model.html (the design-phase schema-of-record) against the raw data, and bakes in the six decisions locked with Anand on 27 Jun. Read alongside posting-catalog.html (which legs each document posts).

The one truth the real data forces

Raw data is never clean, and it never arrives in our shape. Every file proves it — banner and grand-total rows mixed into the data; headers that lie (Educational = an invoice date, TAX 3 = the GST rate, Buyer = a GSTIN); one column holding two facts (Description = Style#Colour, PACK/SIZE = "XL (105 CMS)"); barcodes stored as integers (leading zeros lost); the Season column polluted with Excel dates and four spellings of one cohort; cost recorded above MRP (24 real cases); Jockey arriving in five different distributor layouts.

So the kernel is two tiers. A messy staging layer ingests each source through a per-source profile, splits composites, normalises against alias tables, and validates — flagging, never blocking. Only clean, validated rows are promoted into the canonical kernel. The canonical target is KDPS's own 20-column PT format (pt-file-format.xlsx); the weekly PT-maker is this ingest pipeline.

The norms every table obeys

  1. Money = integer paise (*_paise bigint). Rates / GST% / margins = numeric. Unit cost is taken directly as the vendor's purchase rate (P RATE / SALE RATE / Net Value), never ÷(1+slab). Verified on the Rosetta pair: BASIC = invoice taxable RATE, P RATE ≈ BASIC×1.20.
  2. Barcode = text, non-unique scan-alias. Stock is a count under (barcode, season), never a primary key. Schemes coexist (EAN-13, 7-digit internal, alphanumeric, leading-zero). 68% of suppliers ship no barcode → KDPS generates.
  3. Season = FK to a season master, never a free date. Reject Excel serials; normalise SS25 ≡ SS-25 via brand_season_map.
  4. Three keys per document: surrogate bigint PK · business doc-number ({FY}/{store}/{seq}) · idempotency UUID for offline writes.
  5. Dirty masters carry canonical + alias (brand, vendor, season, taxonomy). Never join on raw vendor text; dedup to a surrogate id.
  6. Composite columns split on ingest (Style#Colour, size+measurement, gender+garment).
  7. Sentinels (0, ., N/A, NA) → NULL; banner / total rows (null natural key) are dropped, never stored.
  8. Snapshot masters onto documents; ledgers append-only; SCD-2 where money depends on history (gstin, gst_slab, cost, price, brand_terms, amm).
  9. Dimension columns on every ledger leg — store · brand · season · state_gstin — so the books read per store/brand/state without reconstruction.
  10. Data-quality = constraints + flag-don't-block (§15). A bad row raises a visible exception; the floor keeps working.
