1The rule we used to choose

Use the simplest tool that works — and always the cheapest of the three that does the job. In rising cost and risk: plain code → classical machine-learning → an AI model (LLM). Money numbers are always computed by plain code — an AI model is never trusted to do the maths.

This isn't caution for its own sake. On real quantitative tasks, an AI model alone scored ~36% accuracy; given a plain calculator tool to do the sums, the same setup hit ~95%. So: code computes, AI explains, a human decides. (npj Digital Medicine, 2025.)

3Which models, and why "best tool for each"

  • Google Gemini (Flash / Pro) — reading invoices & documents, writing the digest. Fast, cheap, strong at images. (Your choice for image — confirmed as the right one.)
  • Claude Sonnet or Gemini Pro — the conversational assistant, where reasoning and tool-use matter most. Swappable; both run on Vertex.
  • Classical machine-learning — forecasting, size curves, anomaly scoring. No AI model involved; it's the right and cheaper engine.
  • Plain code — every rupee, every posting, every tax number. Exact, every time.

All AI runs through Vertex AI; the assistant reaches data only through a read-only, access-scoped layer — it can never write the books.

The headline: the whole system runs at about ₹25,000/month. All the AI combined is under ₹2,000 of that — the cost is the always-on database, not the intelligence. (In USD: ~$248 lean / ~$294 expected / ~$625 high.)

The cheapest levers, in order

  • Skip database high-availability at launch — biggest single saving (~₹20k); add it when zero-downtime truly matters.
  • Right-size the database — start small, grow with load.
  • Keep WhatsApp on "utility," not "marketing" — utility messages are ~7× cheaper; service replies are free.
  • Model choice — Flash/Flash-Lite for digests & reading; pick the top model only for the assistant. Even then it's a rounding error.

5Two honest flags (so they don't bite us later)

Data location: all stored data — the database, files, every record — sits in India (Mumbai). But Google does not yet give a formal guarantee that the AI model's processing happens inside India for the generative models (its committed regions today are US/EU/Japan/Singapore/Korea). Our design already handles this: the AI only ever sees safe, edge data and computed numbers — never raw customer or payment details. We confirm the live position before go-live, and the system works regardless of which model we point at.
