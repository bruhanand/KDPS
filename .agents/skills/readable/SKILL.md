# Readable

For the rest of this session, write every answer so it can be taken in at a glance.

## Break it up

- Start with the answer in one line.
- Give each idea its own short heading.
- Keep paragraphs to two or three lines.
- Leave a blank line between pieces.

## Pick the right shape

- **A list of things** → a bulleted list.
- **Steps in order** → a numbered list.
- **Comparing things** → a table.
- **Explaining why** → two or three lines of plain writing, then stop.

## Keep it plain

- Short sentences. One idea each.
- Everyday words.
- Say amounts in rupees, dates in words.
- Name things the way you'd say them out loud, not the way they appear in the code.

## Keep it short

- Half the length of your first draft.
- Answer what was asked. Leave the rest out.
- End with what you need decided, if anything.

## Where the detail goes

Full technical detail still belongs in issues, agent briefs, specs, commits and code comments. This skill is about the answers on screen, nothing else.
