SQL reading cheat sheet

Enough SQL to read any query in a code review and know what comes back — and to catch the one that's dangerous. You're reading, not writing.

The sentence

Read it right-to-left as English
SELECT   sku_id, SUM(qty) AS on_hand   -- ① which columns
FROM     stock_movement                -- ② which table
WHERE    store = 'Store-7'            -- ③ which rows
GROUP BY sku_id                         -- ④ buckets for the SUM
ORDER BY on_hand DESC;                -- ⑤ sort, biggest first

The words

SELECTwhich columns to return (* = all)
FROMwhich table
WHEREwhich rows to keep
GROUP BYbucket rows for a total
ORDER BYsort (DESC = biggest first)
LIMIT 10only the first 10 rows
JOINcombine two tables (Lesson 6)

Aggregates (squash rows → one number)

SUM(x)total — e.g. stock on hand
COUNT(*)how many rows
AVG(x)average
MIN / MAXsmallest / largest
AS namerename the output column

How to read any query (the method)

A query is written top-down but easiest to read in the order the database runs it. Read FROM first, SELECT almost last.

Step 0 — read or write?

SELECTsafe — just looks
INSERT/UPDATE/DELETEchanges data — check its WHERE

Then walk it in this order

1 FROM/JOINwhat rows am I starting from?
2 WHEREwhich rows survive?
3 GROUP BYbucket into piles?
4 HAVINGwhich piles survive?
5 SELECTwhat does each output row show?
6 ORDER BY/LIMITsorted how, how many?

Read vs write

Reads (safe — look only)

SELECTfetch rows; changes nothing

Writes (change data)

INSERTadd a new row
UPDATEchange existing rows
DELETEremove rows

KDPS queries you'll recognise

Stock on hand, one SKU
SELECT SUM(qty) FROM stock_movement WHERE sku_id = 'NK-AM90-WHT-8';
On hand for every SKU in every store
SELECT sku_id, store, SUM(qty) AS on_hand
FROM stock_movement GROUP BY sku_id, store;
How many pieces sold today
SELECT COUNT(*) FROM stock_movement
WHERE type = 'SALE' AND created_at >= '2026-06-20';
🚩 The one dangerous pattern. An UPDATE or DELETE with no WHERE hits every row in the table. 
-- 😱 wipes everything        -- ✅ scoped to one document
DELETE FROM stock_movement;     DELETE FROM stock_movement WHERE document = 'BILL#902';
🧭 Reviewer's reflex — three questions for any query:  (1) Read or write?  (2) Which table?  (3) What's the WHERE — does it scope to exactly the rows meant?  Answer those and you know what it does and where its effects land.
