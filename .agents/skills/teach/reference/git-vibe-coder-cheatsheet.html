Git — the vibe coder's cheat sheet

The handful of commands that actually matter when you're directing AI to build KDPS. Not all of Git — just enough to never lose work and to undo fearlessly.

🧭 One idea to hold: Git is a ledger for your code — exactly like your stock ledger. Each commit is a movement: nothing is overwritten, the whole history is kept, and you can rewind to any past point. If you understood the stock ledger, you already understand Git.

👀 See — what's going on

git status

Your most-used command. What's changed since the last save point? Run it constantly.

git log --oneline

The list of your save points (commits), newest first — your code's ledger.

git diff

Shows the exact lines that changed. Great for reviewing what the AI just did.

💾 Save — make a checkpoint

git add .

Stage all your current changes, ready to save.

git commit -m "add GST to bill total"

Make the save point, with a short note to your future self. This is the checkpoint you can always return to.

git add . && git commit -m "…"

The everyday combo: stage everything, then save it in one go.

↩️ Undo — go back

git restore .

The panic button. Throws away all uncommitted changes → back to your last save point. (Use when the AI made a mess you haven't committed.)

git restore path/to/file

Same, but only undo one file.

git revert <commit>

Safely undo a commit you already saved, by adding a new "undo" entry — keeps the history honest (very ledger-like).

restore vs revert: not saved yet → restore.  Already committed → revert.

🌿 Branch — a safe sandbox

git switch -c try-discounts

Make a side copy to try something risky. Your working version stays untouched.

git switch main

Hop back to your main version.

git merge try-discounts

If the experiment worked, fold it back in. If it didn't, just delete the branch and walk away.

☁️ Remote — your cloud backup

git push

Send your save points up to the cloud (e.g. GitHub) — a backup, and where the app deploys from.

git pull

Bring down changes from the cloud copy.

git clone <url>

Copy an existing cloud project onto your machine.

🔒 Keep secrets out

.gitignore

A list of files Git must never save — junk folders, and crucially secrets.

Golden rule: never commit a password, API key or DB login. Once in history it's there forever — even after you delete it. Add it to .gitignore before your first commit.

The fearless loop

commit (good state)→ let the AI change things→ does it work?→ yes: commit again / no: git restore .

Commit before you let the AI loose, and the worst case is always "throw it away and I'm back where I started."

Five habits that keep you safe

  • Commit before any big AI change. That's your restore point.
  • Commit small and often. Tiny save points mean you rewind minutes, not days.
  • Write a real message. "add return-window alert" — not "stuff", "wip", or "asdf".
  • Run git status and git diff before you commit — know what you're saving.
  • Risky idea? Make a branch. Experiments never threaten your working version.
