# Mission: Building & Shipping KDPS

## Why
Anand is personally architecting KDPS — an AI-powered operating system for a 50+ store Indian fashion retailer — and the design is nearly done. He's a **vibe coder**: he directs AI to write the code rather than hand-writing it. He wants to fill the knowledge gaps that stand between "I designed the spine" and "I shipped working software my stores actually run on" — so he can build the ERP **without fear of how things work under the hood**, and judge whether what the AI produces is right.

*(Evolved 19 Jun 2026 from "The Language of Building KDPS" — vocabulary to follow design discussions — now that the design is nearly done and he's moving to the build.)*

## Success looks like
- See any KDPS feature as the **four boxes** (screen / brain / memory / outside world) and know where each new piece of code belongs.
- Use **Git** as a fearless undo button — break things, recover, never lose work.
- Read the **database schema** the AI builds for his spine and sanity-check it against his ledger design.
- **Judge AI-generated code**: spot when a change is wrong, in the wrong box, or the AI is bluffing — and push back in the right words.
- Get a vertical slice from his local machine to **live in a store**.

## Constraints
- Plain language, short, non-technical. No overexplaining.
- Anything he keeps is an **HTML** document, never markdown.
- He's busy running the design + build — lessons must be quick wins.
- Starting point: very basic CLI, can read some code and use the terminal — not much beyond that.

## Out of scope
- Hand-writing production code from a blank file (he vibe-codes — the skill is *directing & judging* AI, not typing it all himself).
- Deep ML / statistics math.
- Tally / accounting mechanics beyond what's needed to design.
