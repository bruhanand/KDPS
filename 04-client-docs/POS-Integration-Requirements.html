POS Integration Requirements

The data KDPS's new system needs to send to, and read from, the POS — so the two stay in step. Please confirm what is available today and the timeline for the rest.

Context. KDPS is building a system that holds the master stock and documents. The POS stays the billing counter. We are not asking you to change billing — we need a clean two-way data exchange (APIs). The shared key on both sides is the barcode.

1.How the integration works

  • Two directions: KDPS sends stock and documents to the POS, and reads sales and stock back.
  • Timing: near-real-time where possible (every few minutes), plus one end-of-day batch as the daily close.
  • Key: the barcode identifies the item on both sides.

4.Capabilities to confirm

These few answers decide how the integration is built. Two are load-bearing (marked ★).

  1. ★ Can the API accept a pending-inward / incoming-transfer quantity (stock the store will receive but hasn't yet)?
  2. ★ Can the POS export line-item sales (the sale report) automatically via API or scheduled file?
  3. Can the POS accept a hold / reservation that reduces sellable quantity without removing the stock?
  4. How does the POS record a customer exchange — as a single "exchange", or as a return + a new sale? Does it link to the original bill?
  5. Can the POS accept and auto-apply offer / EOSS rules sent by us (later phase)?
  6. Is the barcode an acceptable join key for all of the above, in both directions?
  7. What method (REST API / webhook / scheduled file export), frequency, authentication and rate limits can you support?
  8. Which of these are available today, and what is the timeline for the rest?

5.Note on approach

KDPS is building this so the POS connection sits behind a single, clean interface. Wherever the POS can provide the above, we use it directly. Where it cannot — or until it can — KDPS will build to this same specification (with offline-capable billing) so the rollout is not held up. A clear list of what is available now, and timelines for the rest, lets us plan accordingly.
